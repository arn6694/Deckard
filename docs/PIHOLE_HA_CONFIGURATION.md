## How DNS Failover Works

When a client has multiple nameservers configured:

1. **Primary Query:** First nameserver (10.10.10.22) is queried
2. **Timeout Handling:** If no response within timeout (~1-2 seconds), client automatically retries with secondary nameserver (10.10.10.25)
3. **Automatic Fallback:** When primary recovers, clients resume using it (standard resolver behavior)

No special configuration or failover software required - this is built into standard DNS resolver behavior.

## Configuration Details

### Primary Pi-hole (10.10.10.22)

**Environment:**
- Type: Proxmox LXC Container 105
- OS: Debian-based
- Services: pihole-FTL (DNS + Blocking)

**Key Paths:**
- Config: `/etc/pihole/`
- Logs: `/var/log/pihole/`
- FTL Service: `sudo systemctl {start|stop|restart|status} pihole-FTL`

**Upstream DNS:**
- Configured to use BIND9 Primary (10.10.10.4) for authoritative lookups
- Handles recursive queries from clients

### Secondary Pi-hole (10.10.10.25)

**Environment:**
- Type: Raspberry Pi 4 (WiFi)
- OS: Raspberry Pi OS
- Services: pihole-FTL (DNS + Blocking)
- Network: Independent from VPN (CloudFlare upstream for true redundancy)

**Key Paths:**
- Config: `/etc/pihole/`
- Logs: `/var/log/pihole/`
- FTL Service: `sudo systemctl {start|stop|restart|status} pihole-FTL`

**Upstream DNS:**
- CloudFlare (1.1.1.1) for redundancy
- Uses BIND9 Secondary (10.10.10.2) when needed

## Troubleshooting

### DNS Resolution Not Working

```bash
# Test primary directly
dig @10.10.10.22 example.com +short

# Test secondary directly
dig @10.10.10.25 example.com +short

# Check resolver configuration
cat /etc/resolv.conf
```

### Primary Pi-hole Offline

Clients will automatically use secondary (10.10.10.25) - no action required until primary recovers.

### Both Pi-holes Offline

Clients will fall back to any configured external nameservers (Firewalla upstream DNS).

### Service Won't Start

```bash
# Check logs
ssh brian@10.10.10.22 "sudo journalctl -u pihole-FTL -n 20"

# Restart FTL daemon
ssh brian@10.10.10.22 "sudo systemctl restart pihole-FTL"
```
